# 縦に流れる罫線図をフロー図として描く（規模 S）

## 背景

Markdown は既に HTML として整形表示している（`src/viewers/markdown.js`）。
コードブロック内の図は次の3通りで扱っている（`src/viewers/diagram.js`）。

| 種類 | 現状の表示 |
|---|---|
| `mermaid` | 実際の図に描く |
| `┌─┐` で囲んだ層構造が2つ以上 | カードに組み直す（原文と切替） |
| それ以外の罫線・矢印図 | 等幅テキストの字間を補正して表示するだけ |

`agent-dev-tool/copilot_studio/要件定義書.md` の「5. 新業務（To-Be）の流れ」は3番目に当たり、
枠のないテキストの並びとして出るので流れが読み取りにくい。

## 方針

枠（`┌`）を使わず「行＝工程、`▼`/`│`＝つなぎ、`──ラベル──▶`＝横の受け渡し」で書かれた図を
解析し、ノード（角丸の箱）と矢印の HTML/CSS フロー図として描く。既存の「カード／原文」切替と同じ UI で
「フロー／原文」を切り替える。既定はフロー。

解釈の規則:

- `▼` `↓` `│` だけ（＋任意のラベル）の行 → 縦の矢印。ラベルは矢印の横に出す
- `A ──ラベル──▶ B ──▶ C` → 横一列の箱と、ラベル付きの横矢印
- 行末の `──▶ │` のように相手が無い矢印 → 次の段へ合流する矢印として描く
- `工程 ── 補足` のように矢じりの無い `──` → 工程の箱の中に分岐・補足として小さく添える
- `└` `├` で始まる行 → 直前の工程の分岐として箱の下に添える
- `①〜⑳` で始まる工程 → 番号を丸バッジにする

## 受入条件

1. 上記の要件定義書の5章が、箱と矢印のフロー図として表示される。工程①〜⑦、③④の分岐、
   BPO 担当の確認、結果メール以降の横の流れがすべて読める
2. ヘッダーの「フロー／原文」で切り替えられ、原文は従来どおり字間補正つきで表示される
3. 次の図は今までどおりの表示のまま変わらない
   - `├──` `└──` を使ったディレクトリツリー
   - `┌─┐` の層構造（カード表示）
   - 横に複数の列が並ぶ2次元の図（解析対象外と判定してテキスト表示）
4. ライト／ダークの両テーマで読める（既存トークンの色だけを使う）
5. 新しい依存を足さない

## 非目標

- 任意の ASCII アートの完全な図化（2次元配置・ループ・斜めの線は対象外。テキスト表示に任せる）
- Mermaid への変換や、Mermaid の読み込み
- フロー図の編集・ドラッグ・エクスポート
- Markdown 以外（Word など）での専用対応（`decorateProse` 経由で同じ処理が掛かる分は妨げない）
- 元の Markdown ファイルの書き換え

## 触るファイル

- `src/viewers/diagram.js` … フロー解析 `parseFlowDiagram` と描画 `flowChart` を追加、`diagramBlock` で切替
- `src/styles/diagram.css` … フロー図のスタイル

## 検証方法

- `pnpm dev`（ポート 5180）で起動し、`agent-dev-tool/copilot_studio` フォルダを読み込んで
  要件定義書.md の5章をライト／ダークでスクリーンショット確認
- 同じフォルダ内の他の md と、このリポジトリの README.md 等にある罫線図・ツリーの表示が変わらないことを確認
- `pnpm build` が通る
